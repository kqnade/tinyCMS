# Objective

Establish the first production-oriented D1 persistence layer for editorial content, with explicit SQL migrations, Drizzle schema definitions, and verified repository primitives that later admin and publication work can consume.

# Scope

- Own only `packages/database/**`, `migrations/d1/**`, and `pnpm-lock.yaml` in this increment.
- Create the initial D1 migration for authors, posts, immutable post revisions, tags, post-tag relations, media, redirects, publication jobs, site settings, audit events, search chunks, and the FTS5 index described by the design snapshot.
- Add Drizzle schema definitions that match the SQL migration and typed repository primitives for transactional author/post/revision creation and reads.
- Verify migrations, constraints, indexes, foreign keys, revision immutability expectations, and representative repository behavior against local D1 through Vitest.
- Keep all identifiers as lowercase UUIDv7 strings generated by application code, timestamps as epoch milliseconds, booleans as constrained integers, and structured documents as versioned JSON text.
- Use the lifecycle values `draft`, `scheduled`, `publishing`, `published`, `archived`, `failed`, and `trash`; use explicit constrained states for publication jobs.
- This unit is the sole D1 schema and migration owner in the current parallel batch. Other units must not define or consume the schema until this increment is integrated.

# Non-goals

- Admin or public HTTP endpoints.
- R2 object operations, Vectorize synchronization, AI generation, email, likes, or sitemap delivery.
- A migration runner for deployed environments beyond Wrangler's standard D1 migration workflow.
- Changes to root tooling or any application directory.
